premise

agents should be allowed to do real work. they should never be allowed to do irreversible work alone.

beliefs
enforce in the path, not in the prompt.
A code freeze written in instructions didn't stop Replit's agent. A gate the command has to pass through does.
judge the action, not the agent.
The same agent is trusted to read a table and stopped before it drops one.
snapshot before you ask.
Humans make mistakes too. A restore point taken before the command makes even a wrong yes reversible.
two keys for anything irreversible.
The two-person rule protects launch codes and bank vaults. Production deserves the same.

questions

the honest answers.

does it slow my agent down?

Safe commands are checked locally and pass straight through. Only actions your policy marks as risky wait for a human.

is this a sandbox?

No. Sandboxes isolate where code runs. SecondKey controls what an agent may do to the real systems it already has access to. They work well together.

what can't be undone?

Anything outside your systems: an email sent, a payment made, a webhook fired. Those should be set to deny or ask, never allowed automatically. Data written after a restore point also needs merging, which SecondKey flags for you.

what if the agent bypasses the hook?

For databases, run the SQL proxy so raw connections need the second key too. Pair it with scoped, short-lived credentials so the agent never holds a key that skips the gate.

where does my data go?

The free version runs entirely on your machine, and snapshots stay in your own storage. The hosted tiers only see approval metadata unless you choose otherwise.
